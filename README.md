# 曲柄滑块机构运动仿真

内联 SVG + 原生 JavaScript 的曲柄滑块（slider-crank）运动仿真，含一套可复现的自动化验证脚本。
**无任何第三方依赖**，不需要构建步骤，不联网。

运动学模型（全项目唯一公式出处）：

```
x(θ) = r·cosθ + √( L² − r²·sin²θ )          θ = 曲柄转角，逆时针为正
```

## 运行

页面直接用浏览器打开即可（无依赖、无构建）：

```
crank-slider.html            # 主仿真
slider-crank-fixed.html      # 修复版（可对照 slider-crank-buggy.html）
三个参数实验.html              # 参数实验对比图
```

验证脚本需要 Node.js（本项目只用标准库，无需 `npm install`）：

```bash
node verify.js                                  # 主仿真页验收
node audit.js slider-crank-fixed.html           # 期望：OK 未发现问题
node audit.js slider-crank-buggy.html           # 期望：XX 共确认 9 处问题
node smoke.js                                   # 期望：冒烟测试全部通过
node ctest.js                                   # 装配约束对照（两个版本并排打印）
node exp.js                                     # 三个参数实验的定量结果
node expcheck.mjs                               # 期望：OK 全部通过
```

## 验证脚本的工作方式

不起浏览器（沙箱不允许），而是用 `new Function('document','requestAnimationFrame','performance', scriptSrc)`
把 HTML 内嵌的真实脚本注入一个最小 DOM 桩，再用**假时钟**驱动 `requestAnimationFrame` 回调，
逐帧读取 `setAttribute` 之后的坐标值做断言。因此：

- 断言的是**文件里真实运行的代码**，不是另写一遍公式（避免「测试与实现各说各话」）；
- 结果可复现、可回归，不依赖显示器刷新率与人工观察。

桩支持 `createElementNS` / `setAttribute` / `appendChild` / `remove` / `replaceChildren` /
`innerHTML` / `querySelectorAll`，并在派发 `input` 事件前同步控件的 `value`，以模拟真实拖动。

## 三个参数实验（A 组基准 r=30, L=100, ω=2）

| 实验 | 参数 | 行程 | 中点 | a₂/a₁ | 峰值/平均速度 | 周期 |
|---|---|---|---|---|---|---|
| A 基准 | r=30, L=100, ω=2 | 60.0 mm | 100 mm | 7.68% | 3.281 | 3.142 s |
| E1 | r=50（幅度实验） | **100.0 mm** | 100 mm | 13.39% | 3.529 | 3.142 s |
| E2 | L=32（形状实验） | 60.0 mm | **32 mm** | **33.73%** | **4.990** | 3.142 s |
| E3 | ω=4（转速实验） | 60.0 mm | 100 mm | 7.68% | 3.281 | **1.571 s** |

- **E1**：行程 = 2r，随 r 线性增长；形状只因 r/L 变大而轻微变形。
- **E2**：行程只由 r 决定（不变），但 √(L²−r²sin²θ) 的权重随 L 变小而急增（二次谐波 ≈ r²/4L），
  曲线明显歪斜：最外端"爬行"、过中点后急冲，最内点仅 2 mm（= L−r）。
- **E3**：x(θ) 中不含 ω ⇒ 曲线**逐点相同**，只有周期减半。

另记：曲线满足 `x(2π−θ) ≡ x(θ)`（关于 θ=π 对称），故本机构是**对心**曲柄滑块，**无急回**特性。

## 已知边界

- `slider-crank-fixed.html` 的 UI 约束为 `L ≥ r + 5`（曲柄不能过长以免卡死），
  L 滑杆 `min=40`。因此 E2 的 L=32 在该页面上会被夹紧，需直接改常量才能复现
  （L=32, r=30 本身物理合法：根号内最小值 32²−30² = 124 > 0）。
- 主仿真页 `crank-slider.html` 的常量是 `R=30, L=60`，r/L 无滑杆，仅 ω 可调。

## 为什么不用浏览器也能验证

通常这类动画只能靠肉眼判断"看起来对不对"，而脱开、转速漂移这类问题恰恰是肉眼容易漏掉的
（例如连杆脱开在 θ=0 的瞬间偏差为 0，转起来才显现）。本项目改用**可复现的数值验证**：

把 HTML 内嵌的 `<script>` 原样取出，注入一个最小 DOM 桩（实现 `createElementNS` /
`setAttribute` / `appendChild` / `replaceChildren` / `innerHTML` / `querySelectorAll`，
并在派发 `input` 前同步控件 `value` 以模拟真实拖动），再用**假时钟**驱动
`requestAnimationFrame` 回调，逐帧读取写入 SVG 的坐标与脚本内部状态做断言。

这样断言的是**文件里真正跑的代码**，而不是另写一遍公式，避免了"测试与实现各说各话"。

一个具体例子：测转速时不能读页面显示的角度——它是 `θ mod 2π` 的方位角，转 3 圈 + 64°
会显示成 64°，做差值必然丢圈。`verify.js` 改为在内存中插桩暴露脚本内部的 `θ`，
再逐帧做环绕修正后累加（规则：仅当增量 < 0 时补一次 2π）。

## 开发过程中发现并修掉的测试侧缺陷

项目的验证脚本自身也出过错，一并记录在此，因为它们比被测代码的 bug 更有欺骗性：

1. **期望时长错配**：拿全局假时钟的差值当"实际时长"，而该时钟已被同文件前面的片段推进，
   于是 10 s 的测量去比 20 s 的期望值。
2. **角度读取方式错**：读显示值（模 2π）做算术差值，必然丢圈（见上一节）。
3. **环绕修正规则错**：原先写 `|Δ| > π 时减 2π`，会把 `ω=4、Δt=1s` 的真值 `4 rad`
   算成 `4 − 2π = −2.28 rad`；正确规则是仅当 `Δ < 0` 时补一次 2π。
